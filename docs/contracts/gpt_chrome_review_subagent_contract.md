# GPT/Chrome Review Subagent Contract

## Purpose

This contract makes Chrome-controlled GPT review a persistent project capability instead of an ad hoc chat trick.

The subagent is led through the strategy gate owner first, then routed to the relevant module owner. It may review and ideate, but it never becomes source-of-truth.

## Standing Role

| Layer | Rule |
|---|---|
| Lead routing | 필수 / Regime Research owns top-level strategy-gate interpretation |
| Governance owner | Research Governance owns packet discipline, registry linkage, and artifact manifests |
| Module owner | The lane owner owns follow-up implementation only after repo-native validation is defined |
| GPT role | Review and ideation layer |
| Chrome role | Logged-in ChatGPT access and visible UI review layer |
| Source-of-truth | Repo artifacts, exact IDs, registries, raw/runtime sources, broker truth, validation output |

## Trigger

Use `skills/gpt-chrome-review-subagent/SKILL.md` when a task asks to:

- discuss strategy evaluation or development with GPT
- review backtest, replay, lifecycle, cost/slippage, OOS, or leakage evidence
- inspect frontend UI/UX, dashboard blocker visibility, or chart packets through Chrome
- review Slack/EOD wording for blocker-first reporting
- convert GPT feedback into a durable owner/team task

## Required Packet

Every GPT/Chrome review must have a packet generated by:

```powershell
python skills/gpt-chrome-review-subagent/scripts/new_review_packet.py --task-id <task_id> --lane <lane> --objective "<objective>" --artifact <path> --validation "<command>"
```

The packet must name:

- objective
- lane
- owner team
- reviewer team
- source artifacts
- validation commands
- forbidden actions
- return format

## Chrome Timeout Fallback

The default target is the existing Chrome ChatGPT tab named `1. 코딩/투자` when it is available.

If the existing tab times out, freezes, fails to accept input, or fails to return a response within the task's browser timeout, the GPT/Chrome review subagent must not keep hammering the same stuck tab. It must:

1. record the stuck-tab status in the task artifact,
2. open a fresh ChatGPT tab in the same logged-in Chrome profile,
3. paste the same bounded review packet into the fresh tab,
4. capture the fresh-tab response as `review_notes` or `ideation_notes`,
5. record the tab fallback path in the closeout note.

If both the existing tab and the fresh tab fail, the task may continue only when repo-native evidence is sufficient. The closeout must mark GPT capture as `ATTEMPTED_BUT_CHROME_TIMEOUT`, and GPT must not be represented as having reviewed the result.

## Decision Boundary

GPT/Chrome may:

- flag overclaims
- identify missing source, manifest, exact ID, or validation command
- ask reviewer questions
- suggest failure taxonomy or UI visibility improvements
- summarize review notes

GPT/Chrome may not:

- decide strategy acceptance
- decide deployment readiness
- verify broker truth
- calculate or certify PnL, match rates, win rates, or source freshness
- infer lifecycle identity by symbol/date/price/time proximity
- convert missing labels to negatives
- invent chart markers, fills, labels, raw sources, or metrics
- treat a passing test lane as strategy acceptance, deployment readiness, broker truth completion, or real-capital permission

## Test Authority Boundary

When GPT/Chrome reviews tests, validation, CI, or closeout language, it must use:

- `docs/architecture/test_validation_canonicalization_map.md`

GPT/Chrome must preserve this footer in validation wording:

```text
Test results do not modify strategy acceptance status.
Strategy: NOT_ACCEPTED
Deployment: DIAGNOSTIC_ONLY_NOT_DEPLOYMENT_READY
Real Capital: FORBIDDEN
```

## Output Statuses

| Status | Meaning | May Change Registry? |
|---|---|---|
| `review_notes` | Reviewer comments only | No |
| `ideation_notes` | Hypothesis or UX ideas only | No |
| `accepted_to_backlog` | Human owner converted a finding into a repo task | Only through normal task registry update |
| `rejected` | Finding violates rules or lacks evidence | No |

## Closeout

Useful GPT/Chrome findings must be converted into normal repository work:

1. owner team
2. reviewer team
3. read scope
4. write scope
5. artifact location
6. validation command
7. next gate

No one-off GPT review is complete without a packet and a closeout note.
